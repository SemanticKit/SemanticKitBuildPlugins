# Build Plugins

The value is to move repeated manual build and evaluation work into SwiftPM build plugins so the workflow is reproducible, deterministic, and invoked through `swift build`.

The plugin is the captured workflow. It should remove discretion from future runs:

- same inputs from SwiftPM target APIs
- same commands generated by plugin code
- same declared artifacts
- same stdout/stderr diagnostics
- same failure behavior
- no ad hoc shell commands
- no manual OPA invocations during normal use
- no invented per-session process

The doc should explain that purpose first. Then it should document the plugin contracts as automation boundaries, not as shell recipes or stale architecture inventory.

## Plugins

| Plugin | Applied to | Inputs | Command | Declared output |
| --- | --- | --- | --- | --- |
| `RegoPolicyManifest` | a policy target | each `.rego` source file of the target | `RegoPolicyManifestTool --rego <file> --root <root> --output <out>` | `<root with dots>.bundle.tar.gz`: the policy and a `.manifest` whose only root is `<root>` |
| `RegoPolicyCompile` | a policy target, after `RegoPolicyManifest` | each `*.bundle.tar.gz` (or each `.rego` file when the manifest plugin is not applied) | `opa build --target plan --bundle <source bundle>` | `<root with dots>.plan.tar.gz` |
| `RegoPolicyPlanBundle` | a policy target, after `RegoPolicyManifest` | all `*.bundle.tar.gz` of the target (or its `.rego` files) | `opa build --target plan --bundle ...` | `<target>.tar.gz` |
| `RegoPolicyEvaluate` | any Swift target | the `.rego` files of the target and of every target it depends on | `RegoPolicyEvaluateTool plan --opa <opa> --plans <dir> --record <file> --policy ...`, once per target | `RegoPolicyPlans.swift`, a comment line |
| | | each `.swift` file of the target, and the plans | `RegoPolicyEvaluateTool evaluate --plans <dir> --record <file> --source <file>`, once per Swift file | `RegoPolicyFindings.<path in target>.swift`, a comment line |

`<root>` is the policy's path under its target directory without `.rego`: `Sources/AppleHumanInterfaceGuidelines/apple/hig/color/hardcoded_color.rego` has the root `apple/hig/color/hardcoded_color` and must declare `package apple.hig.color.hardcoded_color`. Unique roots keep the per-policy files apart in the target's resource bundle and let `opa build` merge the bundles of a target.

The outputs of the first three plugins are resources of the policy target, for code that links a policy library and evaluates its policies at run time with SwiftOPA; nothing in this repository does that yet. `RegoPolicyEvaluate` does not read them: SwiftPM shows a plugin none of the files that other plugins generate for other targets, so its `plan` command plans the policies it needs itself, into its plugin work directory, and unpacks each plan bundle there for SwiftOPA.

Each command of `RegoPolicyEvaluate` declares only a Swift file holding a comment, so it adds no resources to the target it checks, and the tool rewrites that file only when its line changes. SwiftPM runs the `plan` command again only when a `.rego` file changes, and the `evaluate` command of a Swift file only when that file or the plans change, so editing one file evaluates that file alone.

`opa` is the OPA CLI. The plugins use the `opa` tool SwiftPM provides, then the first `opa` on `PATH`, then `~/.local/bin/opa`, and stop the build with `opa not found` when there is none.

## Policy contract

A policy file declares one package, a `default decision`, and a `decision` rule annotated as the plan entrypoint:

```rego
package apple.hig.presentation.alert_ok_button

default decision := {"deny": [], "warn": [], "note": []}

# METADATA
# entrypoint: true
decision := {"deny": [], "warn": warnings, "note": []}
```

Each entry of `deny`, `warn` and `note` has `rule_id`, `message`, `line`, `column` and `severity`.

`input` is one syntax node. `RegoPolicyEvaluate` gives the nodes of every Swift file to every policy in turn, so a policy states the node it matches:

```rego
call := input
call.type == "FunctionCallExprSyntax"
```

A policy whose every rule body reads `input` only after such a type test finds nothing in a node of any other type, so the evaluator reads those tests from the policy's plan and gives the policy only the nodes of the types they name. It checks this once per policy by evaluating it on a node of a type the tests do not name: if that finds anything, or a rule body reads `input` before testing its type, or passes `input` anywhere but on to the policy's own rules, the policy gets every node.

A node is the SwiftParser node, written as JSON:

| Field | Value |
| --- | --- |
| `type` | the SwiftSyntax node type, such as `FunctionCallExprSyntax`, `MemberAccessExprSyntax`, `TokenSyntax` |
| `range` | `{"start": {"line", "column"}, "end": {"line", "column"}}`, 1-based, without trivia |
| `token` | on tokens only: `kind` (the token kind's case name, such as `identifier`, `stringSegment`, `leftParen`), `text` and, when `///` or `/** */` comments come before the token, `documentation`: their text, one comment per line |
| `children` | the node's children in source order (`Syntax.children(viewMode: .all)`) |

A modifier call such as `view.help("…")` is a `FunctionCallExprSyntax` whose first child is a `MemberAccessExprSyntax`; its last child is the `DeclReferenceExprSyntax` of the name. A plain call such as `Button("OK")` has the `DeclReferenceExprSyntax` as its first child. The code in `#if` blocks is part of the tree whether or not it is compiled.

## Diagnostics

Each finding prints as

```text
<file>:<line>:<column>: warning: <message> [<rule_id>]
```

with `error` for `deny` entries, `warning` for `warn` entries and `note` for `note` entries. A `deny` entry fails the build.

## Attaching the plugins

A policy target holds `.rego` files and applies the three policy plugins:

```swift
.target(
    name: "AppleHumanInterfaceGuidelines",
    plugins: [
        .plugin(name: "RegoPolicyManifest"),
        .plugin(name: "RegoPolicyCompile"),
        .plugin(name: "RegoPolicyPlanBundle"),
    ]
)
```

A package that wants its Swift checked depends on the policy libraries and applies `RegoPolicyEvaluate`:

```swift
dependencies: [
    .package(url: "https://github.com/SemanticKit/SemanticKitBuildPlugins", branch: "main"),
],
targets: [
    .target(
        name: "App",
        dependencies: [
            .product(name: "AppleHumanInterfaceGuidelines", package: "SemanticKitBuildPlugins"),
            .product(name: "SemanticKitDesignGuidelines", package: "SemanticKitBuildPlugins"),
        ],
        plugins: [
            .plugin(name: "RegoPolicyEvaluate", package: "SemanticKitBuildPlugins"),
        ]
    ),
]
```

`Tests/PolicyConsumer` is such a package. `swift build` in that directory reports every `warn` and `note` rule of both libraries from `PolicyTriggers.swift`. The `deny` rules of `SemanticKitDesignGuidelines` fail a build, so they are proved by `InvariantPolicyTests` instead (see [Tests](#tests)).

## SemanticKit invariants

`SemanticKitDesignGuidelines` holds the SemanticKit invariants as `deny` rules: each one fails the build of a target that depends on the library and applies `RegoPolicyEvaluate`, with the rule's id in the diagnostic. They hold the identity rule: inside the Swift runtime the type is the term's identity, and an IRI is read only at the boundary. A boundary target (a translator into SHACL or SPARQL, the HTTP layer) need not depend on the library, and then the rules do not run there. A format's encoder and decoder may also live in a target the rules run on: inside one, `no_interpolated_identity` lets the format build IRIs from text (see the table).

| Rule | Fails on | Instead |
| --- | --- | --- |
| `no_static_term_enum` | terms kept as statics on a type, or as enum cases. On an enum, struct, class, actor or extension: a static property set to a term (`Term(…)`, `Property(…)`, `Class(…)`, `ObjectProperty(…)` and the other declaration kinds), to an instance of the type it is named after (`static let animal = Animal()`) or to its own name (`static let knows = "knows"`), or a static function returning a term. On an enum, any stored static (`enum Fauna { static let animal = … }`), and a static typed `IRI` or a term kind. An enum named or documented as a vocabulary that has cases or statics: `enum Foaf { case knows, person, agent }`, `enum FoafTerm: String { case knows }`, `/// The FOAF vocabulary.` on `enum Friend { case knows }`. A vocabulary name is the prefix of a published vocabulary (`Foaf`, `RDFS`, `Schema`, `ACL`, …) or ends in `Term(s)`, `Vocabulary`, `Vocab`, `Ontology`, `Namespace`, `Properties`, `Classes`, …; vocabulary documentation names a vocabulary, an ontology or a namespace. A struct, class, actor or extension named or documented as a vocabulary that has a stored static. A String-raw enum whose raw values are IRIs, prefixed names or the term's local name (`case animal = "Animal"`). A static whose value is an IRI is left to `no_static_iri_constant`, so it is reported once. Allowed: `CodingKeys`, spec value sets such as `enum TextDirection: String { case ltr, rtl }`, computed statics such as `static var depth: Int { 64 }`, result builders, and string constants that are not terms on a struct (`static let mediaType = "text/turtle"`) | declare the term in the ontology, so that it is its own type |
| `no_static_iri_constant` | a static property, stored or computed, whose value is an IRI however it is built: typed `IRI`, `URL`, `URI`, `NamedNode` or `IRIRef` (also optional or module-qualified); calling one of their initializers anywhere in its value (`URL(string: "…")!`, `try! IRI(validating: "…")`, `NamedNode("…")`, `IRIKit.IRI.init(…)`); holding an absolute IRI or prefixed-name string, bare or passed to any initializer (`"http://…"`, `"foaf:knows"`, `Namespace("http://…")`, `Prefix("owl", "http://…")`, `Term(iri: "http://…")`); or building a string by interpolation or by `+` with a string (`"\(ns)knows"`, `ns + "knows"`) | the type is the identity. The one static IRI allowed is the type's own projection, `static var iri: IRI { Fauna.namespace.iri }`: computed, and built from no string. The namespace is declared in the ontology's `var body` |
| `no_class_value_constant` | a class read as a static value of its ontology, `<name>Class` on a type: `Foaf.agentClass`, `ACL.readClass` | name the class by its type, `Foaf.Agent` |
| `no_term_registry` | a dictionary keyed by `IRI` or `URL`, whatever it holds; a dictionary keyed by `String` whose values are terms (a term kind such as `Term` or `Property`, or a metatype such as `Term.Type`), written as a type or built as a value, module-qualified or not (`[IRI: Term]`, `[URL: Term]`, `Dictionary<String, Term>`, `[Swift.String: Term]`, `[String: any Term.Type]`, `[String: Term]()`, `Dictionary<IRI, Term>()`, `[IRI: Term].init()`); a dictionary literal keyed by IRIs (`IRI(…)`, `.iri`, `.rawValue`, `"http://…"`) or by term names with term values (`["knows": Knows()]`, `["knows": Property(…)]`); or a type named `…Registry`, declared, extended or used (`TermRegistry.shared`, `var terms: TermRegistry`). String-keyed dictionaries of other values (`[String: String]` headers, `[String: Int]` counts) are allowed | refer to the term by its type |
| `no_interpolated_identity` | an IRI built from an interpolated or concatenated string, anywhere in the target except inside a boundary encoder or decoder: an identifier's initializer given one, however it is spelled (`IRI(rawValue: "\(namespace)\(name)")`, `IRI.init(string: namespace + name)`, `URL(string: "\(base)knows")`, `NamedNode(…)`, `Namespace(…)`); or a built IRI string passed to any other call, bound to a name or returned (`Term("http://example.org/" + name)`, `let knows = "\(namespace)knows"`, `return ns + name`). A built IRI string starts with an absolute IRI or prefixed name, or interpolates or adds a namespace: `ns`, `namespace`, `iri`, `uri`, `url`, `vocab`, or a name ending in `Namespace`, `NS`, `IRI`, `URI` or `URL`. A built string bound to a static is left to `no_static_iri_constant`, and a string given to `Domain`, `Range` and the other term references to `no_term_reference_by_name`. A boundary encoder or decoder is a struct, class, enum or actor named `…Encoder` or `…Decoder` or conforming to `Encoder`, `Decoder`, `TopLevelEncoder` or `TopLevelDecoder`, an extension of one, and a type's own `encode(to:)` and `init(from:)`; a `TurtleParser` is not one. The policy reads the whole file (`SourceFileSyntax`) to see what encloses a node. Allowed: strings that build no IRI, such as `"Hello, \(name)"` and `directory + "/file.txt"`, and IRIs a `TurtleDecoder` builds from prefixed names | the IRI is computed from the namespace at the boundary, in a boundary target |
| `no_individual_graph` | any use or declaration of `IndividualGraph` | individuals live in the RDFCore graph |
| `no_values_of_lookup` | a `values(of:)` call, on a value or bare, or declaration: `Cert.key.values(of: alice)`, `values(of: alice)` | read the property on the individual's type |
| `no_add_modifier_on_declaration` | an `add…` or `isDeclaredBy` modifier on an ontology declaration (`Class`, `Property`, `ObjectProperty`, `DatatypeProperty`, `AnnotationProperty`, `Datatype`, `Individual`, `NamedIndividual`, `Ontology`): `Class("Foo").addLabel(…).addComment(…)`. Modifiers on instances, `Dataset().addGraph(g)`, are allowed | declare `Label`, `Comment` and the rest in the declaration's content; `deprecated()` stays a modifier |
| `no_term_reference_by_name` | `Domain`, `Range`, `SubClassOf`, `SubPropertyOf`, `EquivalentClass`, `EquivalentProperty`, `InverseOf` or `DisjointWith` given a string (also one built with `+` or interpolation), an `IRI(…)` (also through `try!`), an `.iri` or `.rawValue` projection, a `.self` metatype or explicit generic arguments | the natural spelling `Domain(Fauna.Animal)` |
| `no_content_function` | an ontology authored as a function: `func content() -> Content` (also `some Content`, `any Content`), and any `func content` of a type that is `@Ontology` or conforms to `Ontology` | author the ontology as `var body: some Content`, as in SwiftUI |
| `no_mode_flag_helper` | a function named `decode…`, `encode…` or `parse…` that takes a `Bool` (or `Swift.Bool`) parameter and is `private`, `fileprivate` or free (declared as a statement, at the top level or in a function body, rather than as a member): `private func decodeTerm(_ token: String, tsvMode: Bool)`. Members of a coder type (`TurtleDecoder.decode(_:strict:)`) and helpers without a `Bool` are allowed | turn text into a term with an initializer or the `Decodable` conformance of the term type, used by the format's decoder; make each format its own coder type rather than a `Bool` mode (DESIGN-CONTRACT.md rule 15) |

The library also holds `no_dictionary_boundary_plumbing`, a `warn` rule.

## Tests

`opa test Sources Tests/Rego` runs the policy tests. Each test's `input` is the parser output for the line of Swift in the comment above it.

`swift test` runs the evaluator's tests in `Tests/RegoPolicyEvaluateToolTests`, with `opa` on `PATH` or in `~/.local/bin`. They parse the Swift in every fixture comment and check that the fixture is the node the evaluator writes for it, so the Rego tests keep testing what policies see at build time. They also plan and evaluate a `deny` policy and check the diagnostic and the exit status, run the `SemanticKitDesignGuidelines` policies over a Swift file with one banned shape per line (each fails with its rule, the tool exits 1) and over the same file with the intended shapes (the tool exits 0), check which node types each library policy is given, and check how decisions decode.
