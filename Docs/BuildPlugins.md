# Build Plugins

The value is to move repeated manual build and evaluation work into SwiftPM build plugins so the workflow is reproducible, deterministic, and invoked through `swift build`.

The plugin is the captured workflow. It should remove discretion from future runs:

- same inputs from SwiftPM target APIs
- same commands generated by plugin code
- same declared artifacts
- same stdout/stderr diagnostics
- same failure behavior
- no ad hoc shell commands
- no manual OPA invocations during normal use
- no invented per-session process

The doc should explain that purpose first. Then it should document the plugin contracts as automation boundaries, not as shell recipes or stale architecture inventory.
